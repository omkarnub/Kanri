10. Security Architecture & Threat Model

A transparent breakdown of Kanri's cryptographic defenses, Android Keystore integration, threat boundaries, and responsible disclosure policy.

1. SQLCipher AES-256 Storage at Rest

Standard Android applications store Room/SQLite databases in unencrypted plaintext inside the app's internal sandbox. On rooted devices or during ADB backups, unencrypted databases can be extracted trivially.

Kanri integrates the official SQLCipher database engine:

  • Every single database page (4,096 bytes) is encrypted individually using AES-256 in CBC mode with HMAC-SHA512 per-page integrity authentication.
  • The master database encryption passphrase is never stored on disk. It is generated using a secure random seed and stored in the Android Keystore system.

2. Android Keystore Hardware Backing

The Android Keystore protects cryptographic keys inside hardware-backed storage such as the Trusted Execution Environment (TEE) or StrongBox Keymaster:

  • Key material never enters the application's RAM in exportable format.
  • Even if an attacker gains root access to the device filesystem, the Keystore key cannot be extracted directly.

3. BiometricPrompt Hardware Security

When App Lock is enabled in Settings > Security:

  • Authentication is delegated to Android's official androidx.biometric.BiometricPrompt.
  • Kanri never handles raw fingerprint or facial scan data.
  • Auto-Lock triggers immediately upon device screen-off or when the app is placed in the background.

4. Threat Model & Attack Vectors

Potential Threat Risk Level Kanri Defense & Architecture
Remote Server Breach Zero Risk Kanri does not operate remote database or account servers. There is no central server to compromise.
Network Interception Zero Risk Core ledger performs zero network transmissions. Optional Drive sync connects directly via TLS to Google Drive.
Malicious Sideloading Low Risk Official release APKs are signed with a dedicated release key and published with verifiable SHA-256 checksums.
Device Theft (Locked) Low Risk Database is sealed with SQLCipher AES-256 and BiometricPrompt hardware lock.

5. Responsible Vulnerability Disclosure

Kanri welcomes security audits and vulnerability reports from the open-source community:

  • Please report suspected security issues privately via GitHub Security Advisories.
  • Do not file public issues for zero-day vulnerabilities until an advisory and patched release have been coordinated.
